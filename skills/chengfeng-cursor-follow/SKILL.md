# 跟随鼠标转头的角色网页

原理：**角色转头视频 → 帧序列 → 鼠标横坐标选帧**。质感来自视频模型，代码只负责切帧，所以不需要 WebGL，也不需要抠像。

```text
0 开场引导  探测工具 → 一条消息问清角色 / 平台 / 目录 → 等回复
1 角色图    任意文生图，或用户自有角色图：正视、居中、纯色背景
2 转头视频  任意图生视频，同一张首帧各跑一次：看左 / 看右
3 抽帧      scripts/build_frames.py：左段倒放 + 右段，写出 frames/ 与 config.js
4 页面      assets/template/index.html：替换文案，按需调参数
5 验收      浏览器里把鼠标放在左 / 中 / 右截图，确认方向与衔接
```

## 0 开场引导（每次都从这里开始）

用户说“跑一下”“用这个”“试试这个 Skill”，或只给了本仓库链接，意思都是**带他做一个自己的页面**，不是让 Agent 自测。此时：

- 不要自己合成测试视频、拿示例素材跑一遍然后汇报“流程通过”。
- 不要跳过提问直接调用付费模型。

### 0.1 先静默探测，再开口

用一两条只读命令看用户手上有什么，用来给出选项，不要把探测过程讲给用户：

- `python3`、`ffmpeg` 是否可用（缺 ffmpeg 时在提问里一并告诉用户怎么装）。
- 当前环境里有没有可调用的生图 / 图生视频工具：已接入的 MCP、已安装的 CLI（如 `vidmuse`、`fal`、`replicate`）、已设置的 API Key 环境变量。只看是否存在，不打印密钥。
- 用户消息或当前目录里有没有现成的角色图、转头视频。

### 0.2 一条消息问清三件事

用下面的结构发给用户，给出选项和默认值，让他一次回复就能开工。已知的项直接写“已确认”，不再问。

```text
我来带你做一个“跟着鼠标转头”的角色页面，先确认三件事：

1. 角色用什么？
   A. 你发一张现成的角色图（正脸、背景越简单越好）
   B. 你描述一下，我来生成（外观、表情、风格、背景色）
   C. 先用示例：穿红毛衣、表情嫌弃的西施犬，红色背景

2. 图和视频用什么生成？
   A. 【探测到的工具，例如：你已装 xxx CLI，我可以直接调用】
   B. 你在网页端生成（即梦 / 可灵 / Runway 等），我给你提示词和参数，你生成后把视频发回来
   C. 你已经有“看左”“看右”两段视频，直接发给我

3. 页面放哪？默认：当前目录下新建 cursor-follow-<角色名>/

费用参考：一张图 + 两段 5 秒视频。由我直接调用时，开始前会先告诉你大概消耗。
```

没有探测到可调用工具时，第 2 题只保留 B、C，并说明原因。**发完就停下，等用户回复。**

### 0.3 过程中的停顿点

后面每一步做完先给用户看结果，再继续：

| 停顿点 | 给用户看什么 | 等什么 |
|---|---|---|
| 调用付费模型前 | 用哪个模型、生成几次、大概花费 | 用户同意 |
| 角色图出来后 | 图片本身 | 用户认可，或说要改哪里 |
| 两段视频出来后 | 每段抽 5～6 帧拼成的条图 | 用户认可；不合格的那段单独重做 |
| 页面完成后 | 左 / 中 / 右三张截图和页面路径 | 用户试用后的反馈 |

用户选了网页端生成时，用下面的交接卡代替自动调用，然后等用户交回文件：

```text
请在【平台名】里操作：
1. 选“图生视频”，上传这张角色图作为首帧：【图片路径】
2. 时长 5 秒，分辨率 1080p，关闭声音
3. 第一段提示词（看左）：【完整提示词】
4. 第二段提示词（看右）：【完整提示词】
5. 两段都下载下来，发给我，或放到：【目录】/look_left.mp4、look_right.mp4
```

角色图也在网页端生成时，同样先给提示词，拿到图后再发视频交接卡。平台接法与提示词模板见 [references/prompts-and-models.md](references/prompts-and-models.md)。不要假设用户使用某个特定平台。

## 1 角色图

- 正视镜头、居中、头部只占画面中间三分之一。
- **纯色摄影棚背景**，颜色就是最终页面的主色。这是不抠像的前提。
- 用户给的图背景复杂时，先用改图模型换成纯色背景，或建议重新生成。

生成后看一眼再往下走：五官是否正对镜头、背景是否干净。

## 2 转头视频

同一张角色图作首帧，各生成一段：

- **看左**：头转向画面左侧（screen left）约 40°，眼睛跟随。
- **看右**：头转向画面右侧（screen right）约 40°，眼睛跟随。

两段用同一模型、同一分辨率、同一时长（4～6 秒）。要求镜头固定、身体不动、不眨眼、背景不变。

拿到后先抽几帧检查：方向对不对、脸有没有变形、背景有没有闪。不合格的那一段单独重生成。

**不要**用改图模型直接出“看左”“看右”两张关键帧再做首尾帧视频，角色位置和视线容易对不上。原因见 [references/lessons.md](references/lessons.md)。

## 3 抽帧

```bash
python3 <skill>/scripts/build_frames.py \
  --left look_left.mp4 --right look_right.mp4 \
  --out <网页目录> --init-page
```

- 依赖 Python 3 与 ffmpeg。缺 ffmpeg 时先让用户安装。
- 输出 `frames/f000.jpg…`（从最左到最右，中间帧为正视）和 `frames/config.js`（帧数、背景色）。`--init-page` 在目录里还没有 `index.html` 时复制模板。
- 已经有一段从左转到右的视频时用 `--sweep video.mp4`。
- 读脚本输出的 `warnings`：两段首帧差异偏大，说明首帧不是同一张图，正视位置会跳，回到第 2 步。
- 默认每隔 1 帧取 1 帧、宽 1600。页面偏大时用 `--step 3` 或 `--width 1280`。

## 4 页面

模板 `index.html` 自动读取 `frames/config.js`，背景色会跟视频一致；视频背景偏浅时自动切换为深色文字。

需要改的：

- 标记为“文案”的文字：品牌、标题、介绍、卡片、旋转提示。按角色性格写，不要保留占位文案。
- 按需调整：`SUBJECT_HEIGHT`（角色占屏高度）、`EASE`（跟随快慢）、`--accent`（强调色）。
- 不需要的块（导航、卡片、角度读数）可以整块删掉。

如果用户项目有自己的设计规范，文案和配色遵循它；布局以“角色居中、文字在两侧不挡脸”为原则。

## 5 验收

在浏览器里打开页面（本地 `file://` 可直接打开），等加载完成后：

1. 鼠标分别放在屏幕最左、正中、最右，**每个位置等 2～3 秒**再截图，缓动需要时间到位。
2. 确认：左边看左、右边看右、正中正视；角度读数跟着变。
3. 检查画面边缘：左右和顶部没有矩形硬边，背景颜色衔接自然。
4. 窄屏（手机宽度）下文字不挡住角色脸。

向用户报告时分开说明：实际生成费用、帧数与体积、截图验证了哪些位置、仍存在的瑕疵。

## 边界

- **只做左右转头。** 这是本 Skill 的全部交互，不扩展到其他方向。
- 分发或上线前提醒用户：角色图若来自网图或他人 IP，需要替换为有权使用的素材。
