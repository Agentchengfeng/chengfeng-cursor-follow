# 主角跟着鼠标转头的网页

交付物是**一个网页**。页面中间的主角形象会跟着鼠标左右转头；形象、转头视频、帧序列都是为这个网页服务的中间产物。

原理：形象的转头视频 → 帧序列 → 鼠标横坐标选帧。质感来自视频模型，代码只负责切帧，不需要 WebGL，也不需要抠像。

```text
第一步  问用户要做什么样的网页                          ← 停：等用户回答
第二步  按网页设计主角，把它做成左右转头视频（核心）      ← 停：花钱前确认一次，之后一路做完
第三步  把视频抽成帧序列
第四步  帧序列放进网页，验收后交付
```

只有两个停顿点。用户确认后，形象图、视频、抽帧、网页一路做完，中间不再停下来让用户逐项看；质量由 Agent 按第二步的检查标准自己把关，不合格自己重做。

用户说“跑一下”“用这个”“试试这个 Skill”，或只给了本仓库链接，意思都是**带他做一个他自己的网页**，从第一步开始。不要自己合成测试素材跑一遍后汇报“流程通过”，也不要跳过提问直接调用付费模型。

## 第一步：问用户要做什么样的网页

只问一句，不列表单。用户消息里已经说了网页或主角时，跳过这一步直接进入第二步。

```text
想做个什么网页、主角用什么？一句话就行，比如“我咖啡店的首页，主角是店里的柴犬”“我的个人主页，主角用猫”。
没想好就回“随便”，我给你配一个。
```

发完停下，等用户回复。

**用户回复任何内容，都算完成了第一步，直接进入第二步。** 例如只回“我想用猫来做”，就是主角 = 猫，网页用途、名称、文案、风格、主色由 Agent 按常识定一版（没线索时默认做成“以这个主角为名字的品牌首页”），写进第二步的确认消息里让用户一起改。**不要再追问第一步没答的项，也不要让用户“继续补充表单”。**

## 第二步：做转头视频（核心）

网页效果好不好，几乎全看这两段视频。代码只负责切帧，视频里转头不稳、脸变形、背景闪，网页上都会原样出现。

### 2.1 花钱前确认一次

先静默探测，不要把探测过程讲给用户：

- `python3`、`ffmpeg` 是否可用（缺 ffmpeg 时告诉用户怎么装）。
- 有没有可调用的生图 / 图生视频工具：已接入的 MCP、已安装的 CLI（如 `vidmuse`、`fal`、`replicate`）、已设置的 API Key 环境变量。只看是否存在，不打印密钥。能查价格和余额就查。

然后用**一条消息**把方案、生成方式和费用一起给用户确认：

```text
网页：【用途】·【名称】·【一句话介绍】·【页面放哪些内容、按钮】（没说的是我定的，想改直接说）
主角方案：【形象、表情性格，为什么适合这个网页】
背景色（= 网页主色）：【#hex】，文案语气：【一句话】

用什么生成？
A. 【探测到的工具】直接调用：一张图 + 两段 5 秒视频约【费用】；
   某段不合格时我会自己重做一次，最多约【含重做的上限】
B. 你在网页端生成（即梦 / 可灵 / Runway 等），我给你一张照着点的操作卡
C. 你已经有这个形象“看左”“看右”的两段视频，直接发我

确认后我会一路做完，最后直接给你网页。
```

没探测到可调用工具时只给 B、C。用户给了现成形象图时，方案里只说背景色和语气；图的背景复杂，先换成纯色背景。**发完停下，用户确认后不再停。**

### 2.2 形象图

- 正视镜头、居中、头部只占画面中间三分之一，给转头留出左右空间。
- 纯色摄影棚背景，颜色就是 2.1 定的网页主色。这是不抠像的前提。
- 16:9，1080p。

Agent 自己看一眼：五官正对镜头、背景干净无杂物。不合格直接重生成，不用问用户。

### 2.3 两段转头视频

同一张形象图作首帧，各生成一段。两段用同一模型、同一分辨率、同一时长（5 秒）：

```text
Locked-off static camera, no camera movement, no zoom.
The 【character】 slowly and smoothly turns its head about 40 degrees
toward the 【left / right】 edge of the frame (screen 【left / right】),
and its eyes follow the same direction.
One single continuous motion that finishes at the end of the clip.
Body stays still. Expression stays the same, no blinking, no mouth opening.
Background stays the same plain 【color】. No text, no subtitles.
```

- 方向一定写 “screen left / edge of the frame”。写 “its left” 会被理解成角色自己的左，方向就反了。
- 两段可以并行提交。长任务遇到网关超时（如 HTTP 524），后台多半仍在生成并已扣费：先查任务或资产列表，不要立刻重发。
- **不要**用改图模型先出“看左”“看右”两张关键帧再做首尾帧视频，形象位置和视线容易对不上。

### 2.4 自己检查，不合格就修

每段抽 6 帧拼成一张条图（例如 `ffmpeg -i v.mp4 -vf "select='not(mod(n\,24))',scale=420:-1,tile=6x1" -frames:v 1 strip.jpg`），逐项检查：

| 问题 | 看哪里 | 怎么修 |
|---|---|---|
| 方向反了 | 看左那段，脸最后朝画面右边 | 提示词强调 “toward the LEFT edge of the frame (screen left)”，重生成 |
| 转得太小 | 最后一帧几乎还是正脸 | 角度改成 50–60°，加 “clearly turns its head” |
| 转得太猛或回头 | 中途转过头又转回来 | 强调 “one single continuous motion, stays at the end” |
| 脸或体型变了 | 后几帧五官、毛色和首帧不像 | 加 “same character, identity unchanged”；换一个一致性更好的模型 |
| 镜头动了 | 形象在画面里整体变大、变小或位移 | 强调 “locked-off static camera, no zoom, no pan” |
| 眨眼、张嘴、多余动作 | 中间帧 | 加 “no blinking, no mouth movement, only the head turns” |
| 背景闪烁或出现杂物 | 各帧背景颜色、边缘 | 强调 “background stays identical plain 【color】”；形象图背景不干净就回 2.2 |
| 头转出画面 | 最后一帧头被裁掉 | 回 2.2，把形象缩小一点、留足左右空间 |

只重做不合格的那一段。每段最多自己重做一次；第二次还不行，停下来把条图给用户看，说明问题和再做一次的费用。

### 2.5 用户选网页端生成时

用操作卡代替自动调用，发完等用户交回文件；拿到后照样按 2.4 检查：

```text
请在【平台名】里操作：
1. 选“图生视频”，上传这张形象图作为首帧：【图片路径】
2. 时长 5 秒，分辨率 1080p，关闭声音
3. 第一段提示词（看左）：【完整提示词】
4. 第二段提示词（看右）：【完整提示词】
5. 两段都下载下来发给我，或放到：【网页目录】/source/look_left.mp4、look_right.mp4
```

形象图也在网页端生成时，先给形象图提示词，拿到图后再发视频操作卡。各平台接法和示例提示词见 [references/prompts-and-models.md](references/prompts-and-models.md)。不要假设用户使用某个特定平台。

## 第三步：抽帧

```bash
python3 <skill>/scripts/build_frames.py \
  --left look_left.mp4 --right look_right.mp4 \
  --out <网页目录> --init-page
```

- 依赖 Python 3 与 ffmpeg。缺 ffmpeg 时先让用户安装。
- 输出 `frames/f000.jpg…`（从最左到最右，中间帧为正视）和 `frames/config.js`（帧数、背景色）。`--init-page` 在目录里还没有 `index.html` 时复制模板。
- 已经有一段从左转到右的视频时用 `--sweep video.mp4`。
- 读脚本输出的 `warnings`：两段首帧差异偏大，说明首帧不是同一张图，正视位置会跳，回到 2.3。
- 默认每隔 1 帧取 1 帧、宽 1600。页面偏大时用 `--step 3` 或 `--width 1280`。

## 第四步：做成网页

网页目录默认是当前目录下的 `<网页名>/`。第三步的 `--init-page` 已放入模板 `index.html`，它自动读取 `frames/config.js`，背景色和视频一致，视频背景偏浅时自动换深色文字。

在模板上把它改成**用户要的那个网页**，而不是保留模板样子：

- **内容**：用第一步的回答替换全部占位文案（标记为“文案”的品牌、标题、介绍、按钮、卡片、导航、旋转提示）。按钮链接填用户给的地址；用户没提的块整块删掉，不留“卡片标题一”这类占位。
- **结构**：按网页用途调整。例如个人主页加联系方式，活动页加时间地点，产品页加功能卡片。主角始终居中，文字放两侧，不挡脸。
- **风格**：强调色、字体、语气按 2.1 的方案；用户有自己的设计规范时遵循它。
- **参数**：`SUBJECT_HEIGHT`（主角占屏高度）、`EASE`（跟随快慢）按页面效果调。

### 验收

在浏览器里打开网页（本地 `file://` 可直接打开），等加载完成后：

1. 鼠标分别放在屏幕最左、正中、最右，**每个位置等 2～3 秒**再截图，缓动需要时间到位。
2. 确认：左边看左、右边看右、正中正视。
3. 画面边缘没有矩形硬边，背景颜色衔接自然。
4. 窄屏（手机宽度）下文字不挡住主角的脸，页面上没有残留占位文案。

交付时给用户：网页路径（直接双击打开即可）、左 / 中 / 右三张截图、实际生成费用、网页体积，以及仍存在的瑕疵。交付时一并附上两段视频的条图，方便用户判断要不要重做某一段。之后按用户反馈改文案、布局或重做视频。

## 边界

- **只做左右转头。** 这是本 Skill 的全部交互，不扩展到其他方向。
- 分发或上线前提醒用户：形象图若来自网图或他人 IP，需要替换为有权使用的素材。
