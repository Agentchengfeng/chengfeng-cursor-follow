# 主角跟着鼠标转头的网页

交付物是**一个网页**。页面中间的主角形象会跟着鼠标左右转头；形象、转头视频、帧序列都是为这个网页服务的中间产物。

原理：形象的转头视频 → 帧序列 → 鼠标横坐标选帧。质感来自视频模型，代码只负责切帧，不需要 WebGL，也不需要抠像。

```text
第一步  问用户要做什么样的网页
第二步  理解用户的意思，设计主角形象，把形象做成左右转头素材
第三步  按脚本把转头素材抽成帧序列
第四步  做成网页：用户的内容 + 帧序列，验收后交付
```

用户说“跑一下”“用这个”“试试这个 Skill”，或只给了本仓库链接，意思都是**带他做一个他自己的网页**，从第一步开始。不要自己合成测试素材跑一遍后汇报“流程通过”，也不要跳过提问直接调用付费模型。

## 第一步：问用户要做什么样的网页

用一条消息问清网页本身，给例子和默认值，让用户一次回复就能开工。**这一步只问网页，不问视频模型和平台。** 用户消息里已经说清的项不再问。

```text
我来帮你做一个网页：页面中间有个主角，会跟着访客的鼠标转头看过去。先说说这个网页：

1. 做什么用的网页？
   例如：产品 / 工具首页、个人主页、活动或发布页、店铺 / 品牌首页、作品集
2. 名字和一句话介绍是什么？（例如：“Grumpo — 一只会审判你的狗”）
3. 页面上要放哪些内容？
   例如：大标题、一段介绍、按钮（写什么、链到哪）、几张卡片、导航
4. 主角想要什么形象？
   A. 已有形象：发我图片（吉祥物、IP、宠物照片都行）
   B. 给个方向，我来设计（例如“一只高冷的橘猫”“戴耳机的小机器人”）
   C. 不确定，我根据网页来提方案
5. 风格和主色有偏好吗？（例如：暗红、复古、极简、可爱；没有就由我根据网页定）

只回你知道的就行，没说的我按网页的用途来定。
```

发完就停下，等用户回复。

## 第二步：设计主角形象，做成左右转头素材

### 2.1 形象方案

根据第一步的回答提一个方案，给用户确认后再生成：

- **形象**：是谁、长什么样、什么表情和性格，为什么适合这个网页（例如：工具产品用专注、靠谱的形象；活动页用夸张、有梗的形象）。
- **背景色 = 网页主色**：形象图用纯色摄影棚背景，这个颜色就是网页的底色。这是不抠像的前提。
- **文案语气**：网页标题和介绍用什么口吻，和形象性格一致。

用户已经给了形象图时，只确认背景色和语气；图的背景复杂时，建议换成纯色背景或重新生成。

### 2.2 确定用什么生成

先静默探测，再问用户，不要把探测过程讲给用户：

- `python3`、`ffmpeg` 是否可用（缺 ffmpeg 时告诉用户怎么装）。
- 有没有可调用的生图 / 图生视频工具：已接入的 MCP、已安装的 CLI（如 `vidmuse`、`fal`、`replicate`）、已设置的 API Key 环境变量。只看是否存在，不打印密钥。

然后和形象方案放在同一条消息里问：

```text
形象和转头素材用什么生成？
A. 【探测到的工具，例如：你已装 xxx，我直接调用；预计一张图 + 两段 5 秒视频，约【费用】】
B. 你在网页端生成（即梦 / 可灵 / Runway 等），我给你一张照着点的操作卡
C. 你已经有这个形象“看左”“看右”的两段视频，直接发我
```

没探测到可调用工具时只给 B、C。调用付费模型前必须得到用户同意。

### 2.3 生成形象图

- 正视镜头、居中、头部只占画面中间三分之一；纯色背景用 2.1 定的主色。
- 生成后给用户看图，认可了再往下走。

### 2.4 生成左右转头视频

同一张形象图作首帧，各生成一段：

- **看左**：头转向画面左侧（screen left）约 40°，眼睛跟随。
- **看右**：头转向画面右侧（screen right）约 40°，眼睛跟随。

两段用同一模型、同一分辨率、同一时长（4～6 秒）。要求镜头固定、身体不动、不眨眼、背景不变。拿到后每段抽 5～6 帧拼成条图给用户看：方向对不对、脸有没有变形、背景有没有闪。不合格的那段单独重做。

**不要**用改图模型直接出“看左”“看右”两张关键帧再做首尾帧视频，形象位置和视线容易对不上。原因见 [references/lessons.md](references/lessons.md)。

用户选网页端生成时，用操作卡代替自动调用，然后等用户交回文件：

```text
请在【平台名】里操作：
1. 选“图生视频”，上传这张形象图作为首帧：【图片路径】
2. 时长 5 秒，分辨率 1080p，关闭声音
3. 第一段提示词（看左）：【完整提示词】
4. 第二段提示词（看右）：【完整提示词】
5. 两段都下载下来发给我，或放到：【网页目录】/source/look_left.mp4、look_right.mp4
```

形象图也在网页端生成时，先给形象图提示词，拿到图后再发视频操作卡。提示词模板和各平台接法见 [references/prompts-and-models.md](references/prompts-and-models.md)。不要假设用户使用某个特定平台。

## 第三步：抽帧

```bash
python3 <skill>/scripts/build_frames.py \
  --left look_left.mp4 --right look_right.mp4 \
  --out <网页目录> --init-page
```

- 依赖 Python 3 与 ffmpeg。缺 ffmpeg 时先让用户安装。
- 输出 `frames/f000.jpg…`（从最左到最右，中间帧为正视）和 `frames/config.js`（帧数、背景色）。`--init-page` 在目录里还没有 `index.html` 时复制模板。
- 已经有一段从左转到右的视频时用 `--sweep video.mp4`。
- 读脚本输出的 `warnings`：两段首帧差异偏大，说明首帧不是同一张图，正视位置会跳，回到 2.4。
- 默认每隔 1 帧取 1 帧、宽 1600。页面偏大时用 `--step 3` 或 `--width 1280`。

## 第四步：做成网页

网页目录默认是当前目录下的 `<网页名>/`。第三步的 `--init-page` 已放入模板 `index.html`，它自动读取 `frames/config.js`，背景色和视频一致，视频背景偏浅时自动换深色文字。

在模板上把它改成**用户要的那个网页**，而不是保留模板样子：

- **内容**：用第一步的回答替换全部占位文案（标记为“文案”的品牌、标题、介绍、按钮、卡片、导航、旋转提示）。按钮链接填用户给的地址；用户没提的块整块删掉，不留“卡片标题一”这类占位。
- **结构**：按网页用途调整。例如个人主页加联系方式，活动页加时间地点，产品页加功能卡片。主角始终居中，文字放两侧，不挡脸。
- **风格**：强调色、字体、语气按 2.1 的方案；用户有自己的设计规范时遵循它。
- **参数**：`SUBJECT_HEIGHT`（主角占屏高度）、`EASE`（跟随快慢）按页面效果调。

### 验收

在浏览器里打开网页（本地 `file://` 可直接打开），等加载完成后：

1. 鼠标分别放在屏幕最左、正中、最右，**每个位置等 2～3 秒**再截图，缓动需要时间到位。
2. 确认：左边看左、右边看右、正中正视。
3. 画面边缘没有矩形硬边，背景颜色衔接自然。
4. 窄屏（手机宽度）下文字不挡住主角的脸，页面上没有残留占位文案。

交付时给用户：网页路径（直接双击打开即可）、左 / 中 / 右三张截图、实际生成费用、网页体积，以及仍存在的瑕疵。之后按用户反馈改文案、布局或重做素材。

## 边界

- **只做左右转头。** 这是本 Skill 的全部交互，不扩展到其他方向。
- 分发或上线前提醒用户：形象图若来自网图或他人 IP，需要替换为有权使用的素材。
