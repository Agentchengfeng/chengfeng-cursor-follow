# 主角跟着鼠标转头的网页

交付物是**一个网页**。页面中间的主角会跟着鼠标左右转头；形象图、转头视频、帧序列都是为这个网页服务的中间产物。

原理：主角的转头视频 → 帧序列 → 鼠标横坐标选帧。质感来自视频，代码只负责切帧，不需要 WebGL，也不需要抠像。

```text
开场    说明先需要主角图，询问用户是否有现成图
第一步  取得主角形象图：用户提供，或 Agent 生图
第二步  做视频：同一张图做“看左”“看右”两段（本地有工具就直接生成，没有就引导用户）
第三步  抽帧
第四步  做成网页，交付；之后陪用户一步步改内容
```

原则：

- **先确认图源，再进入视频**：现成图就接收并检查；没有图就先生成图或给用户生图提示词。不能把“有没有图”当成隐含分支。
- **本地有工具就直接生成视频**：图检查通过后，环境里有可调用的图生视频工具（MCP、CLI、API），Agent 直接用这张图作首帧生成两段视频，不把活交给用户；交付时报告实际花费。
- **没有工具才引导用户**：交接消息必须说清三件事：选“图生视频”、上传这张图作为首帧、两段各生成 5 秒左右；再附工具地址和“看左 / 看右”两段提示词。不附模型介绍、费用或其他设置。
- **不在对话里指定或推荐模型**，也不说哪个模型“已验证”。用什么工具、什么模型由用户的环境决定；用户问起再说。

用户说“跑一下”“用这个”“试试这个 Skill”，或只给了本仓库链接，意思都是**带他做一个他自己的网页**，从开场开始。不要自己合成测试素材跑一遍后汇报“流程通过”，不要复述规则，也不要开子 Agent 调研仓库。

## 开场：先确认主角图

先静默看一眼环境，用来决定形象图是由 Agent 生成还是给用户提示词，**不要把探测结果讲给用户**：

- `python3`、`ffmpeg` 是否可用。
- 有没有能直接调用的生图工具：已接入的 MCP、已安装的 CLI、已设置的 API Key 环境变量。只看是否存在，不打印密钥。同时看有没有可调用的图生视频工具，决定第二步由谁生成。

如果用户第一句话已经给了主题，就只发这一句：

```text
我们先需要一张主角图。你有现成的图吗？有就把图发给我；没有我先帮你生成一张正面、纯色背景的图。
```

- 如果用户还没给主题，在上面后面补一句：“如果还没定主角，再告诉我想做什么主题，例如店里的柴犬或一只高冷的猫。”不要在同一轮追问网页文案、名称、按钮等内容。
- 用户给出现成形象图：跳过生图，检查这张图（背景复杂时先换成纯色背景），检查通过后马上进入第二步做视频。
- 用户说没有图：本地有生图工具就直接生图；没有就引导用户去豆包等工具生成（见 1.3），停在这里等用户发回图片。
- 缺 ffmpeg 时在这句话后面补一句怎么装。

## 第一步：生图

### 1.1 Agent 自己定方案

根据主题直接定下来，交付时告诉用户：

- **形象**：长什么样、什么表情性格。要有辨识度，性格一眼能看出来（例如慵懒、嫌弃、好奇）。
- **背景色 = 网页主色**：挑一个衬形象的颜色，形象图用这个颜色的纯色背景。这是不抠像的前提。
- **名称和语气**：从主题里取一个名字，文案口吻和形象性格一致。

### 1.2 形象图提示词

按方案填好下面的模板，得到一段完整的英文提示词：

```text
【风格，例如 Pixar-style 3D render / photorealistic photo】 of 【形象：外观、服装】.
【表情与性格】.
The character is perfectly centered in frame, head and shoulders only,
head facing straight toward the camera, eyes looking straight at the viewer.
Head occupies the middle third of the frame.
Background: smooth seamless 【颜色名】 studio backdrop (【#hex】), no objects, no text, no props.
Soft studio lighting, ultra detailed. 16:9.
```

### 1.3 生成

- **本地有可调用的生图工具**：直接用这段提示词生成 16:9 的图，不问用户。
- **本地没有**：引导用户去自己能用的生图工具生成，例如豆包、即梦、ChatGPT。发下面这条，提示词单独放一个代码块，方便一键复制：

  ```text
  先做主角的图。你电脑上没有能直接调用的生图工具，可以去豆包（或即梦、ChatGPT）生成：
  1. 打开豆包，选「图像生成」
  2. 把下面这段提示词粘贴进去，比例选 16:9
  3. 生成后挑一张正脸、背景干净的，发给我
  ```
  紧接着一个只包含提示词的代码块。用户已经说了用哪个工具，就把步骤里的工具名换成它。发完等用户交回图片。

拿到图后 Agent 自己检查：五官正对镜头、头在中间且左右留有空间、背景是干净的纯色。不合格就重新生成（或请用户重新生成），不需要征求确认。

## 第二步：生视频（核心）

网页效果好不好，几乎全看这两段视频。视频里转头不稳、脸变形、背景闪，网页上都会原样出现。

### 2.1 两段提示词

同一张形象图作首帧，各生成一段。只有方向那一处不同：

```text
Locked-off static camera, no camera movement, no zoom.
The 【character】 slowly and smoothly turns its head about 40 degrees
toward the 【left / right】 edge of the frame (screen 【left / right】),
and its eyes follow the same direction.
One single continuous motion that finishes at the end of the clip.
Body stays still. Expression stays the same, no blinking, no mouth opening.
Background stays the same plain 【color】. No text, no subtitles.
```

- 方向一定写 “screen left / edge of the frame”。写 “its left” 会被理解成角色自己的左，方向就反了。
- 两段用同一个工具、同一分辨率、同一时长（5 秒左右），关闭声音。
- **不要**用改图先出“看左”“看右”两张关键帧再做首尾帧视频，形象位置和视线容易对不上。

### 2.2 生成

**本地有可调用的图生视频工具**：直接生成，不问用户。先读该工具的帮助确认模型名和首帧参数，选支持“以图片作首帧”的模型，用这张形象图作首帧，两段并行提交，时长 5 秒左右、关闭声音。长任务遇到网关超时（如 HTTP 524），后台多半仍在生成并已扣费：先查任务或资产列表，不要立刻重发。

**本地没有**：引导用户在自己的视频工具里生成。用户已经说了用哪个工具时，发下面这条（工具只给了名字就先查官方地址）：

  ```text
  用【工具名】做两段转头视频：
  1. 打开【官方地址】，选「图生视频」
  2. 上传这张图作为首帧：【形象图路径】
  3. 分别用下面两段提示词各生成一段，时长 5 秒左右
  4. 做好后两段都发给我（先发看左，再发看右）

  第一段 · 看左：
  ```
  紧接着“看左”提示词的代码块，然后写“第二段 · 看右：”，再接“看右”提示词的代码块。发完等用户交回两段视频。

  “选图生视频、上传这张图作首帧”必须写，漏掉的话用户会用文生视频做出两只不同的角色，两段接不上。

用户还没说用哪个工具时，先问一句：

```text
图好了。接下来要用这张图做两段转头视频，你平时用哪个视频工具？（即梦、可灵、Runway 都行）
```

### 2.3 自己检查，不合格就修

每段抽 6 帧拼成一张条图（例如 `ffmpeg -i v.mp4 -vf "select='not(mod(n\,24))',scale=420:-1,tile=6x1" -frames:v 1 strip.jpg`），逐项检查：

| 问题 | 看哪里 | 怎么修 |
|---|---|---|
| 方向反了 | 看左那段，脸最后朝画面右边 | 强调 “toward the LEFT edge of the frame (screen left)” 后重做 |
| 转得太小 | 最后一帧几乎还是正脸 | 角度改成 50–60°，加 “clearly turns its head” |
| 转过去又转回来 | 中间帧 | 强调 “one single continuous motion, stays at the end” |
| 脸或体型变了 | 后几帧和首帧不像 | 加 “same character, identity unchanged”；仍不行就换一个图生视频模型 |
| 镜头动了 | 形象整体变大、变小或位移 | 强调 “locked-off static camera, no zoom, no pan” |
| 眨眼、张嘴、多余动作 | 中间帧 | 加 “no blinking, no mouth movement, only the head turns” |
| 背景闪烁或出现杂物 | 各帧背景 | 强调 “background stays identical plain 【color】”；形象图背景不干净就回第一步 |
| 头转出画面 | 最后一帧头被裁掉 | 回第一步，把形象缩小一点、留足左右空间 |

只重做不合格的那一段：Agent 自己生成时每段最多自动重做一次，第二次还不行再把条图给用户看；用户手动生成时，把问题和改好的提示词（同样放代码块）发给他重做那一段。

## 第三步：抽帧

```bash
python3 <skill>/scripts/build_frames.py \
  --left look_left.mp4 --right look_right.mp4 \
  --out <网页目录> --init-page
```

- 依赖 Python 3 与 ffmpeg。缺 ffmpeg 时先让用户安装。
- 输出 `frames/f000.jpg…`（从最左到最右，中间帧为正视）和 `frames/config.js`（帧数、背景色）。`--init-page` 在目录里还没有 `index.html` 时复制模板。
- 已经有一段从左转到右的视频时用 `--sweep video.mp4`。
- 读脚本输出的 `warnings`：两段首帧差异偏大，说明首帧不是同一张图，正视位置会跳，回到第二步。
- 默认每隔 1 帧取 1 帧、宽 1600。页面偏大时用 `--step 3` 或 `--width 1280`。

## 第四步：做成网页，交付，再陪用户改

网页目录默认是当前目录下的 `<名称>/`，名称用 1.1 定的名字。第三步的 `--init-page` 已放入模板 `index.html`，它自动读取 `frames/config.js`，背景色和视频一致，视频背景偏浅时自动换深色文字。

先用默认内容把网页做完整，不留占位：

- **文案**：按主题和形象性格写一版名称、大标题、一句介绍、一个按钮。按钮没有链接时先指向 `#`。模板里用不上的块（多余的卡片、导航项）直接删掉，不留“卡片标题一”这类占位。
- **风格**：强调色按 1.1 的方案；用户有自己的设计规范时遵循它。主角始终居中，文字放两侧，不挡脸。
- **参数**：`SUBJECT_HEIGHT`（主角占屏高度）、`EASE`（跟随快慢）按页面效果调。

### 验收

在浏览器里打开网页（本地 `file://` 可直接打开），等加载完成后：

1. 鼠标分别放在屏幕最左、正中、最右，**每个位置等 2～3 秒**再截图，缓动需要时间到位。
2. 确认：左边看左、右边看右、正中正视。
3. 画面边缘没有矩形硬边，背景颜色衔接自然。
4. 窄屏（手机宽度）下文字不挡住主角的脸，页面上没有残留占位文案。

交付消息先给成品，再引导下一步：

```text
做好了：【网页路径】（双击就能打开，动动鼠标试试）
【左 / 中 / 右三张截图】

我先替你定了这些，都可以改：
- 名字「…」、标题「…」、介绍「…」
- 按钮「…」，现在还没有链接
- 主色 【#hex】
本次花费：【实际费用；用户自己生成的就不写】

接下来可以直接跟我说，例如：
- “标题改成……”“介绍写……”
- “按钮叫‘联系我’，链到……”
- “加一块营业时间 / 联系方式 / 作品展示”
- “想换个表情 / 换只猫”（会重新生成图和视频）
```

之后按用户的话一项项改。只改文字、链接、布局时直接改网页，不重新生成视频。

## 边界

- **只做左右转头。** 这是本 Skill 的全部交互，不扩展到其他方向。
- 分发或上线前提醒用户：形象图若来自网图或他人 IP，需要替换为有权使用的素材。
